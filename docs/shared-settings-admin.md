# 共有設定・管理画面仕様

最終更新: 2026-10-19

## 概要

`/admin` の「端末への反映」タブから、各ダッシュボードへ配信する設定値と配信対象を管理する。設定値はD1の `shared_settings` に保存し、バナー画像はR2に保存する。サイトは設定と画像情報を定期取得し、配信対象が有効な値をブラウザーへ反映する。

## 管理できる値

- 日付指定の予定 (`countdownDates`)
- 毎年繰り返す予定 (`yearlyCountdownDates`)
- チャイム時刻と時刻ごとのチャイム・予鈴フラグ (`userChimeTimes`)
- チャイム、予鈴、横型バナー、縦型バナーの表示・有効状態
- 横型バナー画像と縦型バナー画像
- 各設定の端末への反映可否

カウントダウン予定は日付、表示名、色を持つ。チャイム時刻は `HH:mm`、チャイムと予鈴の有効状態はそれぞれ真偽値で保存する。

## 保存・反映の流れ

1. 管理画面は共有設定とバナー一覧をAPIから読み込む。
2. 設定値の保存は管理者専用の `PUT /api/settings` を使用する。管理画面からの保存では、端末への反映対象から外した設定値も保存できる。
3. 「反映対象」の保存は同じAPIの `apply` フィールドを更新する。反映対象が無効の設定は、一般サイトからの自動保存でサーバー値が上書きされない。
4. サイトは起動時に共有設定とバナー一覧を取得し、適用対象の設定をブラウザー状態へ反映する。
5. 起動後は15秒間隔で再取得する。タブが再表示されたとき、またはフォーカスされたときは直ちに再取得する。
6. チャイム再生にはブラウザーの音声再生制限があるため、サイト起動後に利用者が一度画面をクリックする必要がある。

## バナー画像

横型と縦型を別々に登録する。対応形式はPNG、JPEG、WebP、GIF、AVIF。1ファイルの上限は10 MiB。推奨寸法は横型が1700×300 px、縦型が920×1600 px。

画像本体はR2の `banners/horizontal` と `banners/vertical` に保存する。上書きで差し替え、管理画面から削除できる。管理画面およびサイトからの読み取りは公開API、アップロードと削除は管理者認証が必要。

| API | 用途 | 認証 |
| --- | --- | --- |
| `GET /api/banners` | 画像の有無、ETag、サイズ、形式を取得 | 不要 |
| `GET /api/banners/horizontal` | 横型画像を取得 | 不要 |
| `GET /api/banners/vertical` | 縦型画像を取得 | 不要 |
| `PUT /api/banners/horizontal` | 横型画像を登録・差し替え | 管理者 |
| `PUT /api/banners/vertical` | 縦型画像を登録・差し替え | 管理者 |
| `DELETE /api/banners/horizontal` | 横型画像を削除 | 管理者 |
| `DELETE /api/banners/vertical` | 縦型画像を削除 | 管理者 |

## アクセス制御

- `/admin` の設定値・反映対象の編集とバナー画像の追加・差し替え・削除は管理者向け。
- バナー画像の取得はサイト表示に必要なため公開APIとする。
- ローカル開発用の認証バイパスはループバック接続時だけに限定し、本番アクセスには適用しない。

## 2026-10-19 設定保存401の修正

### 原因

Cloudflare Accessアプリの保護先には `/admin` と一部のAPIパスが登録されているが、`/api/settings` は登録されていなかった。設定の読み込み (`GET /api/settings`) は公開APIなので成功する一方、値の保存 (`PUT /api/settings`) はWorkerでAccess認証が必須のため、保護先パス外では `Cf-Access-Jwt-Assertion` ヘッダーが付かず、WorkerがHTTP 401 `Access authentication required` を返していた。権限や設定JSON、D1の保存処理は原因ではない。

### 修正

- Workerは従来どおり `Cf-Access-Jwt-Assertion` を優先して検証し、ヘッダーがないブラウザーリクエストに限って `CF_Authorization` Cookieを同じ署名・発行元・Audience・有効期限検証に通す。DBユーザーとロールの確認も維持する。
- 公開の `GET /api/settings` と `GET /api/banners` をAccessアプリで保護しないまま、管理者の保存・更新操作を認証できる。
- 管理画面はAPIエラー本文を表示し、401の理由を画面で確認できる。

### 確認

- Workerテスト24件成功。Cookieヘッダーからトークンを拾い、WorkerのJWT検証へ送ることを不正トークンで確認した。
- 本番 `video-api` WorkerをVersion ID `c5cfa5f0-75a2-4636-9158-ed2b618af15d` で更新し、PagesのFunctionsを含むビルドを `https://c4fd9319.cp-dashboard-13x.pages.dev` として本番デプロイした。
- 本番データを変更せずにログイン済みブラウザーから認証が通ること、および実保存の成功まではこの確認では未検証。
